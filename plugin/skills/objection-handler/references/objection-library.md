# Objection library

## Early stage (cold replies, first calls)

| Objection | Response |
| --- | --- |
| "Not interested." | "Fair enough. Is that because <problem> isn't an issue for you, or just not a priority right now?" |
| "We already use <tool>." | "Good to know. How is it handling <specific weak spot>? If it's working, I'll leave you be." |
| "Send me some info." | "Happy to. So it's relevant: are you mostly looking at <outcome A> or <outcome B>?" |
| "No budget." | "Makes sense. When does planning start for next year? I'd rather be useful then." |
| "Not the right person." | "Thanks. Who owns <problem> on your team?" |
| "Bad timing." | "When would be better, and what changes then?" Book the date. |

## Mid stage (discovery, demo)

| Objection | Response |
| --- | --- |
| "Too expensive." | "Compared to what? ... What does <problem> cost you today in hours or lost deals?" Then show the maths with their numbers. |
| "We tried something like this and it failed." | "What happened? ... The two most common reasons are <x> and <y>; here's how <peer> avoided them." |
| "I need to talk to my team." | "Of course. Who's involved, and what will they ask you that I can help answer? Want me to join for 15 minutes?" |
| "We'll build it ourselves." | "Could be the right call. How many engineering weeks, and what does maintaining it cost per year?" |

## Late stage (proposal, procurement)

| Objection | Response |
| --- | --- |
| "Your competitor is cheaper." | "They may be. Can we compare line by line? Teams usually find the difference in <onboarding, limits, support>. If they're a better fit, I'll tell you." |
| "Security has concerns." | "Which ones? I'll send the security pack today and can set up a call with our security lead this week." |
| "Can you do a bigger discount?" | Trade, don't give: "I can look at that if we can <sign by date / commit annually / be a reference>." |
| "Legal needs more time." | "Understood. Which clauses? We have pre-approved alternatives for the common ones." |

## Proof matching

| Concern type | Best proof |
| --- | --- |
| Value | Peer result with numbers; their own maths |
| Risk of switching | Migration plan, timeline, a reference who switched |
| Security and compliance | Documents, certifications, data-flow diagram |
| Adoption | Usage numbers from a similar team, onboarding plan |
| Price | Cost-of-problem calculation, packaging options |
